# Phase 04 Business Case

## Problem

MADAR has completed its first three AWS transformation phases. As more employees need to operate or review AWS resources, individual IAM users and long-lived credentials would create weak lifecycle control, inconsistent permissions and poor scalability.

## Business requirement

Provide centralized workforce access to AWS using corporate identity, SSO, MFA, temporary sessions and role-based authorization.

## Why now

Phase 03 moved a representative legacy workload into AWS and proved the application/data cutover. The next operational risk is no longer only infrastructure; it is **who can access the cloud environment, with what privileges, and how quickly that access can be changed or revoked.**

## Success criteria

- employee identity is centralized,
- access is group-based,
- MFA/SSO works,
- sessions use temporary credentials,
- least-privilege boundaries are tested,
- joiner/mover/leaver lifecycle is validated,
- audit evidence is available,
- paid lab resources are controlled and cleaned up.
